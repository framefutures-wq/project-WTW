# 갈틈 UI / 상세 v2 고정 기준

> 목적: 새 ChatGPT/Codex 세션에서도 UI 감각·제품 방향·신뢰 원칙이 흔들리지 않도록 하는 고정 설계 계약.
> 이 문서는 UI 작업 전에 반드시 읽는다. 대화 기억보다 이 문서를 우선한다.

## 1. 작업 순서

1. ✅ 태백시 / 서울 한강 municipal generic onboarding 완료 (`8af623e`).
2. **현재 단계: 전국 coverage 확대를 잠시 멈추고 UI / 브랜드 시스템 v2를 완성한다.**
3. UI 작업에는 상세 정보구조 v2 + 갈틈 파생정보 레이어 + adaptive media fallback을 포함한다.
4. UI/상세 v2가 안정되면 공식 상세 enrichment 품질을 확대한다.
5. 이후 전국 municipal coverage 확장을 재개한다.

UI 작업 중 데이터 coverage를 핑계로 다시 범위를 넓히지 않는다.

## 2. 갈틈이 보여야 하는 인상

갈틈은 “기능이 있는 행사 DB”가 아니라 **이번에 어디 갈지 결정하게 해주는 놀거리 탐색 서비스**처럼 보여야 한다.

목표 톤:

- 따뜻한 여행 감성
- 선명한 결정감
- 공식정보 신뢰
- 정보가 많아 보여도 복잡하지 않음
- “맹하고 평평한 느낌” 금지

Benchmark:

- Klook: 탐색 효율 / 검색·필터 / 카드 밀도
- Fever: 이미지 존재감 / 감성적 비주얼 톤
- GetYourGuide: 상세 정보 위계 / 핵심 CTA
- 갈틈 고유 강점: 공식정보 신뢰성 / 변경 추적 / 추측하지 않음

## 3. 컬러 시스템

- canvas: 웜 아이보리 `#F7F4EE`
- primary ink: 차콜 `#171A1D`
- secondary ink: `#343A40`
- brand accent / discovery / primary action: 따뜻한 오렌지 `#F26B38` 계열
- official / verified trust state: 절제된 딥그린
- card surface: 흰색 또는 사진 중심

역할:

- 아이보리 = 배경
- 차콜 = 구조와 정보 위계
- 오렌지 = 행동 / 발견 / 갈틈 브랜드
- 딥그린 = 공식 확인 / 신뢰

대략적인 감각 비율:

- neutral 70
- photo + charcoal 20
- orange accent 10

금지:

- 초록/보라/베이지/검정이 제각각 포인트 역할을 하는 상태
- 포인트 색을 화면 전체에 도배
- 회색 텍스트가 너무 옅어 정보가 흐려지는 상태

## 4. 홈 / 카드 UI

홈:

- 검색과 행사 이미지가 주인공.
- 버튼·테두리·칩을 줄여 관리화면 느낌 제거.
- 상단은 “갈틈 → 어디 갈지 찾는다”가 1초 안에 이해되어야 한다.
- 모바일은 PC 축소판이 아니라 별도 정보 밀도와 가독성으로 조정.

행사 카드 기본 위계:

1. 이미지
2. 추천 이유
3. 행사명
4. 날짜
5. 장소

- 카드에서 불필요한 시스템 문구 제거.
- 추천 영역은 일반 목록과 시각적으로 구분.
- 박스 수보다 이미지, 타이포, 명도 대비, 여백으로 위계 형성.

## 5. 상세페이지 정보구조 v2

기준 샘플:

- 서울 왕궁수문장 교대의식

기본 순서:
**대표사진 → 제목 → 언제/어디서 → 공식 안내 CTA → 볼거리 → 시간표 → 프로그램 → 소개 → 지도/주변행사 → 출처**

원칙:

- 날짜·장소·문의 등을 똑같은 회색 박스로 나열하지 않는다.
- 사용자가 가장 먼저 궁금한 “언제 / 어디서”를 크게 보여준다.
- 주요 일정은 문장 나열이 아니라 timeline.
- 프로그램은 개별 card.
- 공식 출처 / 마지막 확인은 하단.
- optional 정보가 없으면 “미확인” 박스를 만들지 않고 섹션 자체를 숨긴다.
- 정보량에 따라 상세 레이아웃이 압축/확장되는 adaptive 구조.

## 6. 상세 데이터 3층 구조

상세를 풍성하게 만들되 사실을 창작하지 않는다.

### 1) 공식 사실

공식 근거가 있는:

- 행사명
- 날짜 / 시간
- 장소
- 프로그램
- 요금
- 주차
- 문의
- 운영시간
- 공식 소개
- 공식 이미지

### 2) 갈틈이 안전하게 계산·재구성한 정보

새 사실을 만들지 않고 기존 사실로 계산 가능한:

- 요일
- 행사 기간
- D-day
- 진행중 / 예정 상태
- 오늘 볼 수 있는 프로그램
- 날짜별 일정 재구성
- 위치 기반 거리

### 3) 갈틈이 연결한 탐색 정보

- 같은 날짜 / 지역 행사
- 같은 장소의 다른 행사
- 비슷한 테마 행사
- 주변 행사

금지:

- 공식 근거 없는 주차 가능 여부
- 공식 근거 없는 반려동물 가능 여부
- 공식 근거 없는 요금
- 공식 근거 없는 프로그램 내용
- “페이지를 채우기 위해” 사실을 추측하는 것

## 7. 미디어 fallback 정책

갤러리 빈칸을 채우기 위해 실제 행사처럼 보이는 이미지를 창작하지 않는다.

우선순위:

1. 행사/주최기관 공식 대표 이미지
2. 사용 권한과 공식 출처를 확인할 수 있는 공식 추가 이미지
3. 이미지가 적으면 갤러리 수 자체를 줄이고 레이아웃을 이미지 수에 맞춘다
4. 이미지가 0장이면 갈틈 타이포·도형·카테고리 아이콘 기반의 **명백한 정보형 브랜드 그래픽**
5. 실제 행사 사진으로 오인될 수 있는 AI 생성 현장/장소/프로그램 이미지 금지

Adaptive media:

- 4~5장: gallery
- 2장: main 1 + secondary 1
- 1장: 한 장을 크게 사용하는 완성형 layout
- 0장: 날짜/지역/카테고리/공식정보 중심 브랜드 graphic + 정보 중심 상세

구현 상태(2026-09-23 production):

1. ✅ 1장/0장 상세 fallback 완료 — commit `f5dd796`.
   - 1장: 기존 bounded frame/contain/확대 유지.
   - 0장·로드 실패: 지역·테마·기간을 활용한 CSS 정보형 갈틈 브랜드 그래픽.
2. ✅ 주변 행사 / 비슷한 행사 등 상세 탐색 보강 — commit `c12fbef`.
3. ✅ 공식 추가 이미지 데이터 구조/API 확장 — commit `0db657f`; production migration `0021` 및 TourAPI `firstimage2` secondary backfill 활성화.
4. ✅ 2장 adaptive media — commit `096ea81`; desktop/mobile production 검증 완료.
5. ✅ UI v2 큰 파트 desktop/mobile 통합 회귀 → build → deploy → production public verify 완료.
6. 4~5장 gallery는 공식 이미지 3장 이상을 실제로 확보할 수 있는 근거가 생길 때만 확장한다.

현재 EventItem/detail은 대표 이미지 `image_url` 1장 구조이므로, gallery를 위해 UI 단계에서 API/D1을 선행 확장하지 않는다.

빈 썸네일 슬롯을 만들지 않는다.

이미지가 부족하면:

- timeline
- 지도
- 공식 fact
- 프로그램 card
- 주변행사
  같은 **검증된 정보의 시각화**로 밀도를 만든다.

## 8. 작업 방식

- UI를 CSS 몇 줄씩 찔끔 수정하며 사용자에게 계속 확인시키지 않는다.
- 홈 / 카드 / 상세 / 모바일을 한 디자인 시스템으로 다룬다.
- 실제 viewport에서 비교사이트와 나란히 보며 검증한다.
- 기능 테스트 통과만으로 “UI 완료”라고 판단하지 않는다.
- production 배포 전 desktop/mobile 실제 화면을 검증한다.
- 사용자에게 “대충 고쳤으니 한번 봐달라”는 식으로 반복 QA를 넘기지 않는다.
- 새 세션에서 UI 방향을 다시 추측하지 않는다. 이 문서를 읽고 그대로 이어간다.

## 9. 새 세션에서의 시작 문장

새 ChatGPT/Codex 세션에서는 먼저:
**“AGENTS.md, PROJECT_CONTEXT.md, NEXT_CHAT_HANDOFF.md, docs/UI_V2_DIRECTION.md를 읽고 현재 working tree와 origin/main을 확인한 뒤, 기존 결정을 바꾸지 말고 중단 지점부터 이어서 작업해.”**

이 문서의 UI/상세 방향을 변경하려면 사용자의 명시적 새 결정을 우선한다.


## 10. 2026-09-26 홈 상단 hierarchy / 공통 가로 레일 보정

사용자 production 검수로 홈 UI를 제한적으로 다시 열었다. 기존 v2 색상·카드·상세 방향은 유지하되 다음을 새 고정 기준으로 추가한다.

- 데스크톱에서 hero, 본문 핵심 surface, 신뢰영역, footer는 서로 다른 legacy max-width를 쓰지 않고 **하나의 시각적 가로 레일**로 정렬한다.
- footer가 header/main보다 눈에 띄게 짧아지는 상태를 허용하지 않는다.
- 상단은 너무 압축하지 않는다. 행사 이미지 + 큰 제목 + 검색창이 첫 화면의 주인공이어야 하며, 검색창은 작은 보조 컨트롤처럼 보이면 안 된다.
- 다만 상단을 키운다는 이유로 필터/카드 구조를 새로 만들거나 첫 결과 접근성을 과도하게 늦추지 않는다.
- 이번 보정 기준의 desktop hero는 약 220px 수준이며, 검색 field/CTA는 약 44px 수준으로 이전보다 한 단계 더 명확한 primary action hierarchy를 가진다.
- 모바일은 별도 밀도를 유지하고 2열 카드/overflow-free 계약을 계속 지킨다.


## 11. 2026-09-26 홈 카드 / 추천 섹션 위계 보정

홈 결과영역은 추천과 전체 목록이 같은 평면에 놓이지 않도록 한다.

- `이번 주말 먼저 볼 곳`은 강한 카드 박스가 아니라 **절제된 editorial surface + 더 큰 제목 + 오렌지 추천 이유**로 먼저 읽히게 한다.
- `더 둘러보기`는 충분한 상단 여백과 divider로 두 번째 레벨임을 분명히 한다.
- 카드 정보 위계는 이미지 → 추천 이유 → 행사명 → 날짜 → 장소를 유지하되, 행사명과 날짜 대비를 한 단계 강화한다.
- 데스크톱 4열 / 모바일 2열 구조는 유지한다.
- 카드 위계 강화를 위해 불필요한 배지·테두리·새 메타데이터를 추가하지 않는다.


## 12. 2026-09-26 하단 신뢰영역 / footer 마감

- 홈 하단은 오렌지 안내박스 → 검은 footer로 급격히 끊기지 않는다.
- 신뢰영역은 밝은 웜 surface + 절제된 딥그린 포인트를 사용해 공식정보 신뢰 역할을 맡는다.
- footer는 별도 검은 박스가 아니라 본문과 이어지는 밝은 웜 브랜드 마감으로 처리한다.
- production에서 `운영 준비 중`처럼 미완성 서비스로 오해될 문구를 노출하지 않는다.
- footer의 SEO landing 링크와 공식정보 기반 신뢰 문구는 유지하되 정보 밀도를 낮게 유지한다.
