# 행사 상세 페이지 UX 사전 점검

## 점검 범위

운영 D1, 운영 API, TourAPI를 호출하지 않고 `src/App.tsx`, 상세 대화상자 CSS, Worker의 상세 API 계약, 기존 로컬 fixture와 브라우저 테스트 구조를 확인했다. 상세는 현재 목록 위에 여는 modal route이며, `/api/events/:id`가 행사와 evidence를 반환한다.

## 기존 구조와 정보 우선순위

상세는 대표 이미지 → 지역/검증 배지 → 행사명 → 샘플 안내·신뢰정보 → 일정·장소·비용·반려동물·개최 상태·확인 시각·출처 → 설명·태그·근거·출처 링크 순서였다. 사용자가 방문 여부를 판단하는 핵심인 날짜와 장소가 설명과 신뢰 영역 뒤에 있어 첫 화면에서 늦게 보일 수 있었다.

현재 공개 상세의 표시 원칙은 다음과 같다.

1. 행사명과 대표 이미지
2. 일정, 장소·주소와 확인된 부가정보
3. 필요한 경우의 행사 상태 안내
4. 행사 소개, 공식 문의와 실제 공식 안내 링크
5. 작은 출처·마지막 확인일과 목록 복귀

일반 부가정보가 `unknown`이면 행 자체를 숨긴다. 비용·주차·반려동물·운영시간·예약·전화·공식 홈페이지는 확인된 값이 있을 때만 표시한다. 개최·취소·연기·일정 변경처럼 방문 결정에 직접 영향을 주는 상태는 숨기지 않는다.

TourAPI 원문, evidence, provenance, raw API field와 좌표는 공개 UI에 표시하지 않는다. 이 데이터는 DB와 내부 검증 API 계약에 보존한다. `tel`은 TourAPI의 공식 문의 필드 중 단일 완전 전화번호만 정규화해 `tel:` 링크로 제공하며, 복수 번호·내선 범위·기관명 혼합 값은 노출하지 않는다. 공식 안내 CTA는 신뢰 검증된 공식 URL만 사용하며 TourAPI 문서 URL은 행사 홈페이지로 표시하지 않는다.

## 발견한 문제와 수정

- 날짜가 원시 `YYYY-MM-DD` 두 값으로만 보여 하루 행사도 범위처럼 보였다. 한국어 읽기 형식으로 표시하고 하루 행사는 한 날짜로 표시했다.
- 설명이 핵심 일정·장소보다 먼저 나와 판단 정보가 아래로 밀렸다. 핵심 메타데이터를 먼저 읽도록 순서를 조정했다.
- 빈 주소·빈 설명·빈 비용 문자열이 빈 줄 또는 빈 값으로 남을 수 있었다. 주소/설명 section은 값이 있을 때만 표시하고 비용은 `비용 정보 확인 필요`로 표시한다. 비용 미확인을 무료로 추정하지 않는다.
- 상세 API의 404와 네트워크/5xx 오류가 같은 화면으로 처리됐다. 이제 “행사를 찾을 수 없어요”와 재시도 가능한 “잠시 정보를 불러오지 못했어요”를 구분한다.
- 상세를 닫는 X만 있어 목록 복귀 동선이 약했다. 실제 동작인 `목록으로 돌아가기` 버튼을 추가했다.
- API 오류 원문이 사용자에게 노출될 수 있었다. 내부 오류 문자열 대신 중립적인 재시도 문구만 표시한다.

## 신뢰정보와 공식 출처

기존 `TrustInfo`를 재사용했다. 확인됨·확인 필요·변경됨 상태, 확인 날짜, 출처 유형, 검증된 공식 안내 링크가 있을 때만 링크를 표시한다. 확인 필요는 중립적인 영역으로 유지하고 내부 status reason이나 HTTP 용어를 노출하지 않는다. TourAPI 원문 링크가 존재할 때만 기존 원문 버튼을 표시하며 빈 링크 버튼은 만들지 않는다.

companion suitability나 내부 fact tag를 새로 표시하지 않았다.

## 반응형·접근성 점검

상세 dialog 폭은 화면 폭에서 여백을 뺀 값으로 제한되고, 본문 값에는 `overflow-wrap`이 적용되어 긴 행사명·장소·주소가 화면을 밀어내지 않는다. 대표 이미지는 기존 높이와 `Scene` fallback을 유지한다. 모바일 본문 패딩과 제목 크기 규칙을 재사용하며 360px, 390px, 430px에서 별도 overflow가 생기지 않는 구조를 확인했다.

기존 h2, 버튼, 외부 링크 semantics, 이미지 alt, dialog Escape/닫기와 opener 포커스 복귀를 유지했다. 새 복귀 버튼도 일반 button으로 키보드 접근이 가능하다.

## QA 상태

정상 행사, 비용 미확인, 공식 링크 없음, 긴 제목·주소·설명, 하루/장기 일정, 포스터·사진형 이미지, not-found(404), API 오류를 로컬 mock 응답으로 검증할 수 있는 구조를 확인했다. 운영 D1 장애로 실데이터 브라우저 검증과 Cloudflare 배포는 수행하지 않는다. 기존 전체 단위·통합 테스트와 로컬 mock 상세 상태 검증을 완료한 뒤 D1 복구 후 운영 회귀를 다시 수행해야 한다.

## 보류한 항목

- URL/query 기반의 별도 상세 route와 브라우저 뒤로가기 상태 보존은 현재 modal 구조를 유지하기 위해 보류했다.
- 지도, 거리, 예약, 저장, 공유, companion 필터, fact tag UI와 설명 요약은 구현하지 않았다.
- 이미지 변환·CDN·source selection은 이미지 파이프라인 범위 밖이므로 변경하지 않았다.
