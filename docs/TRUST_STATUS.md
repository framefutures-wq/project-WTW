# 행사 신뢰상태

2026-09-19 UTC, 원격 D1 `weekend-mwohae-production` 전체 실제 행사 263건에 기존 공식 출처 감사 `official-1ee80f67c3fb0955d4e0087a`를 재사용한다. 외부 페이지 수집, TourAPI 상세 수집, 공식 출처 감사를 다시 실행하지 않았다.

## 판정 규칙 (trust-v1)

- `confirmed` / 확인됨: 공식성 `official=1`, 접근 `ok`, 공식성 근거 excerpt와 content hash가 존재하는 링크에서 행사명·시작일·종료일·장소 모두 확인된다. 필드 비교가 `match`이거나 TourAPI 값은 없지만 공식 값과 해당 회차의 검토 근거가 있는 `not_comparable`여야 한다. 요금·주소·취소 여부 등은 별도로 미확인일 수 있다. 확인됨은 개최를 보증하거나 취소가 없음을 뜻하지 않는다.
- `needs_review` / 확인 필요: 감사 없음, 감사 기준값과 현재 행사 핵심정보·주소·원출처가 다름, 공식 출처 없음/공식성 불확실, 접근 실패, 핵심정보 부족, 의미 검토가 필요한 불일치 또는 공식 근거 간 충돌. 접근 실패는 비공식 또는 변경의 증거가 아니다. 다른 접근 가능한 공식 출처가 충분하면 실패 링크 하나만으로 확인됨을 막지 않는다.
- `changed` / 변경됨: 접근 가능한 공식 근거에서 명시적인 실질 변경이 확인되는 경우만 허용한다. 검토된 `mismatch`의 시작일·종료일이 모두 유효한 ISO 날짜로 서로 다르면 자동 판정한다. 행사명·장소의 차이, 취소·연기·운영 변경은 정확한 비교 ID·양쪽 값·인용문에 결합된 추가 의미 검토(`material_change`)가 있어야 한다. 운영 관련 문구는 비교 가능한 TourAPI 값이 없어도 같은 검토를 요구한다. 서로 다른 공식 값이 충돌하거나 미해결 핵심 차이가 있으면 확인 필요가 우선한다.

띄어쓰기·유니코드 호환 표기·영문 대소문자만 다른 비교는 동등하게 처리한다. 그 외 주소 포맷·시설 별칭·일원과 세부 구역의 관계는 자동 추론하지 않는다. 추가 검토에서 `equivalent`로 확정하면 동등 처리할 수 있다. 가격 불일치만으로 변경됨 처리하지 않는다. 광고·유료 노출·기존 `verification` 값은 판정 입력으로 사용하지 않는다.

공식성 및 해당 회차의 필드 의미는 이전 감사에서 검토된 근거를 신뢰한다. 원문 키워드 검색으로 취소/연기를 추출하지 않는다. 최신 감사 하나만 사용하며 이전 감사의 유리한 필드를 섞지 않는다. 일치하지 않는 URL 또는 근거 없는 비교는 사용하지 않는다.

## 장소 불일치 재검토

`tourapi-4113071` 문경 가은아자개 장터축제의 저장된 TourAPI 상세 `eventplace`는 `문경 에코월드 주차장`, 공식 비교는 `가은아자개장터 일원`이다. 저장된 상세 overview도 `가은읍 일원`으로 넓게 표현한다. 저장된 공식 페이지 본문에는 장소 이전 공지나 두 구역의 동일/포함 관계를 입증할 설명이 없다. 따라서 단순 표기 차이라고 확정하지도, 실질 장소 변경이라고 확정하지도 않는다. 확인 필요로 유지한다.

[기존 공식 근거](https://mgtpcr-tourism.imweb.me/408)의 2026-09-19 저장본만 재검토했다. 재검토 내용은 `scripts/trust-status-reviews.json`에 비교 ID·양쪽 값·해당 인용문과 함께 기록하고 최종 판정의 `evidence_json`에도 저장한다. 기존 감사의 `mismatch` 기록은 수정하지 않는다.

## 저장 및 실행

비파괴 migration `0004_event_trust_status.sql`은 `event_trust_status` 테이블과 인덱스만 추가한다. 기존 `events`, `sources`, `event_evidence`, 공식 출처 감사 3개 테이블은 수정하지 않는다.

행사별 `trust_status`, `status_reason`, `audit_id`, `evidence_source_id`(공식 링크 FK), `checked_at`(기존 감사/접근 검사 시각), `evaluated_at`(규칙 계산 시각), `decision_method`, `rule_version`, `changed_fields`, `unconfirmed_fields`, `evidence_json`, 검토/접근 실패/실질 변경 후보 플래그를 저장한다. 모든 필드별 근거 URL·비교 ID·인용문·확인 시각은 evidence_json으로 보존한다. 원천 자료가 없으면 checked_at과 근거 FK는 NULL이다. 계산 시각을 새로운 페이지 확인 시각으로 표시하지 않는다.

```sh
# 읽기 전용 계산과 로컬 결과물 생성
node scripts/trust-status.mjs --remote
# migration을 검토하고 최초 1회 적용
npx wrangler d1 migrations apply weekend-mwohae-production --remote --config wrangler.production.jsonc
# 원격 전체 실제 행사 판정 저장 및 원본 보존 검사
node scripts/trust-status.mjs --remote --apply
```

`--remote`를 생략하면 로컬 D1을 사용한다. 저장 직전 원천 데이터가 계산 전과 같은지 검사하고, 저장 후 행사·출처·근거·감사 데이터 전체가 동일한지와 판정 값·외래키를 검사한다. 실행 결과와 SQL은 Git 제외된 `.wrangler/deployment/trust-status/`에 저장한다. 재실행은 행사별 판정 스냅샷만 갱신한다.

이번 테이블은 감사 시점 스냅샷이다. Cron 자동 재판정 및 공개 API/UI 연결은 아직 하지 않는다. 기존 공개용 verification과는 별도 개념이며 이번 결과가 기존 공개 배지를 바꾸지는 않는다. 향후 사용자 노출 전에는 감사 유효기간과 동기화 후 재판정 정책을 정해야 한다. 과거 기록만으로 현재도 접근 가능하다고 표시하면 안 된다. 이 작업은 임의의 유효기간을 만들어 확인 상태를 연장하지 않는다.
