# 목록 탐색 v1

## 범위

운영 D1/API를 바꾸지 않고 기존 `page`/`limit` API를 사용해 행사 목록을 제한적으로 확장한다.

- `PAGE_SIZE = 9`
- `PAGES_PER_BATCH = 4`
- `MAX_VISIBLE_ITEMS = 36`

첫 묶음은 1페이지에서 시작해 9개씩 같은 묶음 안에서 최대 36개까지 보여준다. 36개에 도달하면 숫자 페이지 이동 대신 지역·카테고리로 이동하는 탐색 CTA와 다음 묶음 CTA를 보여준다. 다음 묶음은 이전 카드 DOM을 제거하고 5페이지(37번째 행사)부터 다시 9개로 시작한다. 마지막 묶음은 전체 결과를 넘는 범위를 만들지 않는다.

## 탐색 상태

현재 묶음의 시작 페이지와 그 묶음에서 성공적으로 불러온 페이지 수만 클라이언트 상태로 관리한다. 필터, 검색어, 정렬 또는 날짜가 바뀌면 첫 페이지와 첫 묶음으로 초기화한다. 묶음 이동은 URL에 기록하지 않으며 공유 링크는 항상 첫 묶음으로 시작한다.

같은 화면에서 상세 모달을 열고 닫는 경우 목록 상태와 스크롤이 컴포넌트에 유지된다. 묶음을 이동할 때는 현재 묶음의 로드 페이지 수와 스크롤 위치를 메모해 이전 묶음으로 돌아올 때 가능한 범위에서 복원한다. 이전 묶음 복원은 필요한 페이지를 다시 요청하며 숨겨진 카드 DOM을 쌓지 않는다.

## CTA와 오류

`지역을 바꿔볼까요?`와 `다른 카테고리를 볼까요?`는 값을 자동 선택하지 않고 해당 필터로 스크롤하고 포커스를 이동한다. `다음 행사 보기`와 `이전 행사 보기`는 실제 버튼이며 요청 중 비활성화된다.

첫 페이지 오류는 기존 전체 오류 화면을 사용한다. 추가 페이지 오류는 기존 카드 목록을 유지하고 실패한 페이지만 다시 시도할 수 있게 한다. 응답이 중복 행사를 포함하면 content id(`event.id`)로 같은 묶음에서 한 번만 표시하며 서버 중복은 별도 백엔드 문제로 남긴다.

## 페이지네이션 계약

정렬·필터·날짜 조건은 기존 API 계약을 그대로 전달한다. 프런트는 페이지를 묶어서 보일 뿐 전체 순서를 재정렬하지 않는다. 따라서 서버가 제공하는 Phase 5-0F 날짜 정렬과 9개 페이지 경계가 유지된다. 운영 API나 D1에는 새 조회나 쓰기를 추가하지 않는다.
