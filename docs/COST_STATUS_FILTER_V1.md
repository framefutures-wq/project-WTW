# 비용 상태·사용자 비용 필터 v1

## 확인 범위

운영 D1/API와 TourAPI를 호출하지 않고 저장된 로컬 artifact를 사용했다. 전체 행사 snapshot은 `.wrangler/deployment/tourapi-real.json`이며 행사 263건, 생성 시각은 artifact 파일 기준이다. 이 snapshot의 `cost`는 263건 모두 `unknown`, `price_text`도 263건 모두 비어 있다. 별도 샘플 snapshot 13건은 문구 정규화 QA용으로 사용했다.

TourAPI 현재 저장 경로의 `mapFestival`은 목록 응답에 행사 요금 필드가 없으므로 `cost: "unknown"`, `price_text: null`을 저장한다. 비용이 없다는 뜻이 아니라 현재 저장된 공식 근거에서 행사 전체 요금을 확인하지 못했다는 뜻이다.

## 내부 상태 v1

이번 v1은 `free`, `paid`, `unknown` 세 상태만 사용한다. `mixed`는 별도 운영 상태로 도입하지 않는다. 무료 입장과 일부 유료 프로그램처럼 행사 전체를 단일 상태로 안전하게 표현할 수 없는 문구는 `unknown`으로 유지한다.

- `free`: 입장 무료, 관람 무료, 참가비 무료, 명시적인 무료 체험처럼 행사 이용 비용이 무료라고 직접 확인됨
- `paid`: 입장권·입장료·관람료·참가비의 명시적 금액 또는 행사 자체가 유료라고 확인됨
- `unknown`: 비용 필드 없음/빈 값, 문의·현장 확인·홈페이지 참고, 부가 서비스만 유·무료, 일부 프로그램만 유료, 무료와 유료 근거가 함께 있는 경우

무료 주차·유료 주차·셔틀은 행사 비용으로 승격하지 않는다. 축제·공공기관·야외 행사라는 사실도 비용 상태를 만들지 않는다.

`shared/cost-status.ts`의 `assessCost`는 이미 저장된 공식 비용 문구를 분석할 때 사용할 보수적 로컬 정규화 함수다. 이번 작업에서 운영 행사 값을 재계산하거나 D1에 쓰지 않았다.

## snapshot 분포

| 상태 | 행사 수 | 비율 |
| --- | ---: | ---: |
| free | 0 | 0.0% |
| paid | 0 | 0.0% |
| unknown | 263 | 100.0% |
| mixed | 도입하지 않음 | - |

이는 비용이 모두 무료/유료라는 뜻이 아니라 현재 TourAPI 저장 구조에 행사 요금 근거가 없다는 결과다. 샘플 fixture 13건은 free 7, paid 4, unknown 2로 별도 관리되며 운영 snapshot 분포와 섞지 않았다.

## QA 결과

운영 snapshot의 263건 중 40건을 층화 샘플링해 확인했으며, 모두 `cost=unknown`, `price_text=null`이었다. 따라서 명백한 무료/유료 오분류는 0건이고, 근거 없는 무료·유료 승격도 0건이다. 샘플 fixture 13건은 전수 확인했다. 문구 기반 정규화 경계 사례도 다음 synthetic fixture로 검증했다.

- `입장 무료`, `관람 무료` → free
- `성인 5,000원`, `입장권 10,000원` → paid
- 빈 값, 홈페이지 참고 → unknown
- `무료 주차`, `유료 셔틀버스` → unknown
- `입장 무료 · 체험 비용 별도`, `일부 프로그램 유료` → unknown
- `무료 관람 · 음식 구매 별도` → free (입장은 무료이고 음식 구매는 부가 지출)
- `체험권 5,000원`, `체험비 3,000원` → unknown (행사 전체 입장료로 확대하지 않음)

샘플 fixture에 저장된 일부 `cost=free/paid` 값은 합성 데이터의 명시적인 예시 상태다. 새 정규화 함수와 불일치하는 `체험권` 사례를 운영 데이터 오류로 단정하거나 자동 수정하지 않았다.

## 사용자-facing 비용 필터와 표시

첫 화면 비용 필터는 단일 선택 `전체 / 무료 / 유료`만 노출한다.

- 전체: `cost` query를 보내지 않으며 unknown도 포함
- 무료: `cost=free`
- 유료: `cost=paid`

unknown은 무료·유료 어느 쪽에도 포함하지 않는다. 기존 API의 `cost=unknown` 계약은 회귀 호환을 위해 유지하지만 사용자 UI에는 노출하지 않는다. 비용 표시 문구는 `무료`, `유료`, `비용 정보 확인 필요`로 내부 상태와 분리한다.

select 방식을 유지했다. 비용은 세 가지 단일 상태이고 기존 지역·날짜 UI와 조합되며, chip으로 바꾸면 모바일 필터 행이 불필요하게 길어지므로 현재 화면에서는 select가 더 안정적이다.

## 초기화·빈 결과·모바일

비용 선택은 기존 현재 조건 요약과 모두 지우기/필터 초기화에 연결된다. 전체를 선택하면 조건 요약에서 비용 항목이 사라진다. 무료·유료 결과가 0건이어도 기존 “선택한 조건에 맞는 행사가 없어요” 흐름과 필터 초기화 동선을 사용한다.

360px, 390px, 430px mock 브라우저에서 전체·무료·유료 선택, 조건 요약, 초기화, 가로 overflow를 확인했다.

## 운영 반영 시 남은 작업

TourAPI 또는 공식 evidence에서 행사 전체 요금 필드를 실제로 확보할 때만 `assessCost`를 ingestion의 명시적 입력에 연결할 수 있다. 그 단계에서는 free/paid 근거와 일부 프로그램 비용을 분리하고, 기존 운영 `events.cost`를 별도 migration·backfill 절차로 검증해야 한다. 이번 단계에서는 parser 연결, Worker API, schema, 운영 D1을 변경하지 않았다.
