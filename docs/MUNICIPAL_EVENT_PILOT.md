# 지자체 공식 행사 Pilot — Phase 9A

감사일: 2026-09-20 (Asia/Seoul 기준)

## 목적과 범위

TourAPI를 대체하지 않고, TourAPI가 놓친 주말 외출 후보를 지자체 공식 정보로 **적게 발견 → 선별 → 보강 후보화**할 수 있는지 검증했다. 파주시와 수원시만 대상으로 공식 목록·상세 페이지를 각각 필요한 만큼만 열었으며, 신규 event 등록·schema/migration·crawler·Cron은 만들지 않았다.

## Pilot 지역

- **파주시**: [파주 이달의 문화행사](https://tour.paju.go.kr/user/link/cultural/BD_index.do)는 월별 공식 목록과 축제·공연·교육 항목을 함께 보여 주므로, 대표 축제와 제외 사례를 한 화면에서 검토할 수 있다.
- **수원시**: [수원문화재단 행사정보](https://www.swcf.or.kr/?p=29)는 재단의 축제·행사·공연·전시를 날짜와 장소로 구분해 제공하므로, 대표 야간행사와 시설 상설/워크숍을 함께 비교할 수 있다.

## 집계와 후보

- 총 후보: 10
- MAIN: 4
- NEARBY_ONLY: 3
- EXCLUDE: 3
- REVIEW: 0
- TourAPI 미등록 유효 후보(MAIN/NEARBY_ONLY): 7
- TourAPI exact-title 중복: 0

향후 production 등록 전 사람 검토 대상으로 남길 후보는 문산거리축제, 심학산 둘레길 축제, 수원화성 미디어아트, 파주윈드오케스트라 가을음악회, 수문장 마켓 페스티벌이다. 이 문서는 후보 목록일 뿐이며 이번 단계에서 production 등록은 하지 않았다.

## 중복 확인 안전성 발견

10개 제목을 하나의 exact-title D1 query로 제한했지만 `events.title` 인덱스가 없어 Cloudflare 실행 메타데이터상 **264 rows read**가 발생했다. 이는 full scan에 해당하므로 추가 원격 중복 조회를 중단했다. 이 pilot의 중복 결과는 exact-title 참고값이며, 자동화 전에는 title/date/venue를 포함한 별도 후보 index 또는 ingest 시점의 소형 검색 자료가 필요하다. 이번 Phase 9A에서는 이를 구현하거나 schema를 변경하지 않는다.

## 자동화 전 최소 흐름

1. 지자체별 월간 공식 목록 한 페이지를 사람이 선택한다.
2. 5~10개 후보의 공식 상세를 열어 이름·날짜·장소·공개성을 확인한다.
3. Selection Gate v1을 먼저 적용해 MAIN/NEARBY_ONLY만 보강 후보로 남긴다.
4. 인덱스가 보장된 작은 중복 확인 방법이 준비된 뒤에만 TourAPI 중복을 확인한다.
5. 사람 검토를 통과한 소수 후보만 다음 단계에서 공식정보를 보강한다.

이 흐름은 전국 crawl, 자동 인기점수, 대량 등록 없이도 지자체 공식 행사를 보충할 가능성을 보여 준다.
