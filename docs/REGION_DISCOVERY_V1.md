# 지역 탐색 v1

## 확인 범위

운영 D1/API와 TourAPI를 호출하지 않고 `.wrangler/deployment/tourapi-real.json` snapshot과 현재 Worker·frontend 코드를 확인했다. snapshot 기준 행사 263건이며, `region`, `address`, `lat`, `lng`를 모두 확인할 수 있다.

## 지역 계약

현재 v1은 광역 시·도 수준 단일 선택이다.

- 전국: `region` query를 보내지 않음
- 지역: 기존 query 값인 한글 canonical 값(`서울`, `경기` 등)을 그대로 보냄
- 사용자 label과 query 값은 `shared/region-options.ts`에서 분리해 관리한다.

기존 URL 호환성을 위해 `region=서울` 같은 계약을 변경하지 않았다. 현재 `REGIONS`에는 `전남광주`가 별도 canonical 값으로 포함되어 있어 총 18개 지역 query를 유지한다. TourAPI의 `서울특별시`, `경기도`, `강원특별자치도` 같은 원본 명칭은 ingestion의 `regionName`에서 각각 `서울`, `경기`, `강원`으로 정규화된다. 이번 작업에서 원본 값을 덮어쓰거나 새로운 행정구역 단계를 만들지 않았다.

## 시·군·구 도입 판단

현재 최대 지역은 서울 52건, 경기 45건이다. 결과는 날짜·콘텐츠·비용·검색과 함께 좁힐 수 있고 목록은 페이지 단위이므로 v1에서 시·군·구를 추가하면 첫 화면 복잡도와 query 계약이 먼저 커진다. 이번에는 도입하지 않는다. 특정 광역 지역의 한 날짜 결과가 반복해서 과밀해지거나 사용자 거리 탐색 요구가 확인될 때, 해당 지역부터 2단계 필터를 검토한다.

## 내 주변 찾기 계약

현재 버튼은 가짜 placeholder가 아니다. 사용자가 클릭했을 때만 브라우저 위치 권한을 요청하고, 성공하면 `lat/lng`를 API에 보내 거리순으로 정렬한다. 지역을 함께 선택하면 현재 구현상 해당 지역 범위 안에서 거리순이 적용된다. 위치 정보는 저장하지 않는다는 안내를 함께 표시한다.

향후 위치 기능의 계약은 다음과 같다.

1. 사용자가 `내 주변 찾기`를 눌렀을 때만 권한 요청
2. 성공 시 lat/lng 확보 후 거리순 mode 전환
3. 권한 거부·지원 안 됨·조회 실패 시 기존 지역/날짜 필터 유지와 인라인 안내
4. 지역과 위치를 함께 쓸 때는 현재처럼 지역 범위 안 거리순으로 해석
5. 위치 해제 시 거리순을 날짜순으로 되돌리고 조건 요약의 `내 주변`을 제거

지도·반경·Haversine 계산·새 API는 이번 작업에서 구현하지 않았다. 현재 코드에 있는 거리순 동작만 계약으로 문서화했다.

## UI·초기화·접근성

지역 select는 desktop/mobile 모두 native select로 유지한다. 17개 이상 지역을 chip으로 펼치지 않아 검색창과 위치 버튼을 압박하지 않는다. `전국 어디든`은 빈 region query와 연결되고, 현재 조건 요약에는 선택 지역만 표시된다. 모두 지우기는 region을 빈 값(전국)으로 복귀시키며 location·거리순도 함께 해제한다.

360px, 390px, 430px mock 화면에서 지역 select·검색창·내 주변 버튼의 overflow와 터치 영역을 확인했다. select label, button semantics, keyboard focus, 위치 오류의 `role=alert`를 유지했다.

## 구현 범위와 다음 단계

`shared/region-options.ts`에 기존 query와 사용자 label 매핑을 두고 frontend가 이를 사용하도록 했다. backend, schema, D1, 실제 위치 권한/거리 계산은 변경하지 않았다. 향후 광역 지역 query를 slug로 바꾸려면 기존 한글 URL 호환 redirect/alias와 API validation을 함께 설계해야 한다.
