# 탐색·필터 UX 사전 점검

## 범위와 확인 방법

이번 점검은 운영 D1, 운영 API, TourAPI를 호출하지 않고 현재 프론트 코드와 로컬 샘플 실행 경로를 기준으로 진행했다. 운영 D1 일일 row-read 제한 때문에 실제 운영 데이터의 분포나 서비스 상태를 다시 수집하지 않았다. 화면 동작은 로컬 Worker에 API 응답을 주입하는 브라우저 검증으로 확인했다.

현재 탐색 흐름은 `날짜 → 지역/위치 → 검색 → 누구와 → 무엇을 → 비용` 순서다. 목록 카드는 대표 이미지, 지역·장소, 행사명, 기간, 비용, 신뢰정보를 보여주고 카드 전체를 상세 대화상자로 연다.

## 구현한 변경

- 필터 본문 아래에 현재 날짜, 지역, 동행, 주제, 비용, 검색어, 위치 조건을 작은 텍스트 칩으로 표시했다.
- `모두 지우기`는 모든 필터와 검색어, 직접 선택한 날짜, 위치 정렬을 주말 기본 상태로 되돌린다.
- 결과가 없을 때 직접 선택 날짜 또는 제공 범위 밖 날짜이면 `날짜 바꾸기`와 `필터 초기화`를 함께 제공한다.
- 목록/상세 API 실패 시 기술 오류 문자열 대신 재시도 가능한 사용자 문구를 사용한다.
- 날짜 탭과 조건 칩이 360px~430px 화면에서 가로 overflow를 만들지 않도록 모바일 규칙을 보정했다.

## 상태별 사용자 문구

- 검색 결과 0건: “조건에 맞는 행사가 아직 없어요”와 필터 초기화/조건 확장 안내
- 현재 제공 범위 밖: “현재 확인 가능한 행사 기간 밖이에요”와 날짜 바꾸기
- API 오류: “잠시 연결이 어려워요”와 “잠시 후 다시 시도해 주세요”, 다시 시도

세 상태는 코드의 `error`, `range_outside_available`, 일반 `total === 0` 분기로 구분한다. API 오류 내용을 그대로 출력하지 않는다.

## 반응형·접근성 확인

360px, 390px, 430px 모바일과 태블릿·데스크톱에서 날짜 탭, 검색창, 선택 칩, 카드가 부모 폭을 넘지 않도록 확인했다. 버튼과 select에는 기존 레이블/`aria-pressed`/`aria-label`을 유지했고, 선택 조건 요약과 초기화 버튼도 읽을 수 있는 이름을 갖는다. 카드의 전체 클릭 영역과 이미지 대체 텍스트, 상세 대화상자 포커스 복귀 경로는 기존 구현을 유지했다.

## 보류한 항목

- companion suitability가 운영 D1/API에 반영되기 전까지 실제 `fit` 기반 필터 연결은 하지 않는다. 향후 연결 시 `conditional`을 `fit`과 동일한 결과로 취급하지 않는 것이 원칙이다.
- 전시·야간·자연 등 내부 fact tag 전체를 첫 화면 필터로 늘리지 않았다. 실제 사용 빈도와 운영 suitability를 확인한 뒤 별도 결정한다.
- 위치 기능의 권한·거리 계산과 비용 데이터의 의미는 이번 UI 점검 범위를 넘어선다.
- 운영 D1 장애 해소, API/백엔드 변경, Cloudflare 배포, 이미지·신뢰·태그 로직 변경은 하지 않았다.

## 검증 한계와 다음 단계

로컬 샘플 Worker의 실제 D1 응답은 현재 환경에서 오류가 발생해 기존 실데이터 브라우저 회귀 suite를 완주할 수 없었다. 대신 API 응답을 로컬에서 주입한 브라우저 검증으로 정상 목록, 0건, 오류, 조건 요약/초기화를 확인했다. D1 quota가 복구된 뒤 운영 API 회귀와 실제 행사 카드 확인을 다시 수행해야 한다.
